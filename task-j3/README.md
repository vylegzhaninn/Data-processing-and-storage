# Task J3. Асинхронный обход ресурсов HTTP-сервера («паук»)

## Постановка

Дан сервер (`Task_J3-server.jar student_id [port]`): на GET-запрос он отвечает
`200` и телом `application/json` вида
`{"message": "...", "successors": ["path_1", ...]}`, где successors — URL-пути,
которые тоже нужно обойти, начиная с корня `/`. Обработка одного запроса занимает
от 0 до 12 секунд; весь граф собирается минимум за 120 секунд. Результат работы —
все собранные сообщения, отсортированные лексикографически. Обход обязан
использовать виртуальные потоки (Java 21).

## Запуск

```bash
# 1. Сервер (в отдельном терминале)
java -jar Task_J3-server.jar MaksimVylegzanin        # порт по умолчанию 8080

# 2. Паук
cd task-j3
./gradlew run --args="localhost 8080"                # ./gradlew run --args="<host> <port>"
```

Сообщения печатаются в stdout по одному на строке в лексикографическом порядке
(`String.compareTo`); диагностика (число страниц, время) — в stderr.

> Замечание по сборке сервера: в переданном jar опциональный аргумент `port`
> передаётся в Jetty строкой и приводит к `ClassCastException`; без аргумента
> сервер стартует на 8080 нормально. Локальная проверка ниже выполнялась на
> исправленной копии jar (порт 8087), сам jar не менялся.

## Архитектура

* `Spider` — обход графа:
  * задачи выполняются в пуле `Executors.newVirtualThreadPerTaskExecutor()` —
    на каждый HTTP-запрос свой виртуальный поток; работа почти целиком состоит
    из ожидания сети, поэтому потоки ОС не расходуются, а время обхода близко
    к «глубине графа», а не к сумме времён всех страниц;
  * `visited` (`ConcurrentHashMap.newKeySet()`): путь помечается посещённым
    **строго до** отправки задачи — каждый URL скачивается не более одного раза,
    циклы и дубликаты в `successors` безопасны;
  * полнота обхода: задача рекурсивно дожидается `Future` всех порождённых ею
    задач-наследников, поэтому завершение корневой задачи означает, что весь
    достижимый граф скачан;
  * надёжность: таймаут запроса 30 с (> максимума сервера 12 с), 3 попытки
    на сетевые ошибки/таймаут с паузой 500 мс; не-200 — ошибка с телом ответа.
* `Page` — разбор JSON (Jackson); отсутствие `successors` трактуется как пустой
  список.
* `Main` — аргументы `host port` (по умолчанию `localhost 8080`).

## Проверка на реальном сервере

```bash
java -jar Task_J3-server.jar MaksimVylegzanin 8087   # (копия с исправлением порта)
./gradlew run --args="localhost 8087"
```

Фактический результат: **1001 страница** (корень + 1000 узлов графа) собрана
за **86 секунд** — в пределах отпущенных 120 секунд; последовательный обход при
задержках до 12 с на страницу занял бы десятки минут. Пустые строки в выводе —
это не ошибка: генератор сервера создаёт сообщения случайной длины, включая нулевую.

## Тесты

```bash
./gradlew test
```

Встроенный `com.sun.net.httpserver.HttpServer` отдаёт детерминированный граф
(корень + 15 узлов, задержки 150–400 мс, дубликаты и цикл в `successors`, путь
без ведущего слэша):

* все сообщения собраны, каждый путь скачан ровно один раз (цикл не зацикливает обход);
* результат отсортирован по `String.compareTo`;
* обход идёт параллельно: время меньше суммы задержек графа.
